# MyWhoosh Workout Maker

FTPと区間の時間・%FTPからワークアウトを作り、目標出力を可視化する非公式の個人開発ツールです。
**ZWOエクスポートは試験機能です。計算サンプル・SST・4×8・30/15の4種類について、公式MyWhoosh Workout Builderへの取り込みと、区間数・合計時間の期待値との一致をユーザーが確認しました。MyWhooshアプリへの同期、実走時の出力制御、他のOSや環境での互換性は未検証です。**
本アプリのJSONは再編集用の独自形式です。ZWOとは用途・保持する情報が異なります。

## できること

- FTP入力、ワークアウト名・説明の編集。
- 区間の時間・強度・区分の編集、追加・複製・削除・順序変更。
- 4×8分、30/15、SSTの3プリセット。読み込み後の全区間を編集できます。
- 横軸が経過時間、縦軸が目標W、幅が継続時間に比例する棒グラフ。
- ウォームアップ・高強度／主区間・回復・クールダウン・定常走の色分け。
- 合計時間、時間加重平均の目標W、予定仕事量の計算。
- UTF-8 JSONのダウンロード、ファイル／テキストからの再読込。
- 試験用ZWOのダウンロード。整数秒・FTP比率・区間順を保持し、全区間を`SteadyState`へ変換。

プリセットは自作の編集例です。科学的な最適性や個人への適合性を保証しません。
ウォームアップ・クールダウンも、現段階では一定出力の区間です。

## Windowsで起動する

検証対象はWindows・Python 3.13（64 bit）です。Python 3.13をインストールし、
このリポジトリを取得・展開してから、PowerShellで**プロジェクト直下**へ移動してください。
以下のフォルダー名は、実際の保存先に合わせて変更します。

```powershell
Set-Location -LiteralPath .\mywhoosh-workout-maker
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-cache-dir -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-cache-dir --no-build-isolation --no-deps -e .
.\.venv\Scripts\python.exe -m streamlit run app.py
```

依存ライブラリはプロジェクト専用の`.venv`へ導入します。Activate.ps1を使わないので、
PowerShellの実行ポリシーの変更は不要です。初回の依存取得にはインターネット接続が必要です。
`py`が見つからない場合は、Python 3.13の導入を確認してください。
`ModuleNotFoundError: workout_maker`が出る場合は、上記の`-e .`のコマンドを
プロジェクト直下で実行してください。

PCのブラウザで `http://127.0.0.1:8501` を開きます。終了はターミナルでCtrl+Cです。
8501番ポートが使用中なら、起動コマンドの末尾に`--server.port 8502`を指定してください。
2回目以降は、プロジェクト直下で最後の起動コマンドだけを実行します。

同梱設定はPC内の接続だけを受け付け、Streamlitの利用統計送信も無効にしています。
スマートフォン対応やStreamlitのオンラインデプロイは今回の公開範囲に含めません。
固定依存はWindows・CPython 3.13.16で確認したバージョンの記録です。
他のOSやPythonバージョンでの再現性、配布物のハッシュまで固定した再現性は未検証です。

## 操作

1. 「プリセット・JSONを読み込む」でプリセットを選び、読み込みボタンを押します。
2. FTPを設定します。W・平均出力・予定仕事量が連動して変わります。
3. 「編集する区間」で対象を選び、分・秒・%FTP・区分を設定して「区間の変更を適用」を押します。
4. 必要に応じて追加・複製・削除・並べ替えます。最後の1区間は削除できません。
5. 「JSONを保存」でファイルをダウンロードします。
6. 再開時はJSONをアップロードして「ファイルから読み込む」を押します。テキストの貼り付けも可能です。
7. ZWOの検証用ファイルが必要な場合は、下部の「ZWOをダウンロード（試験）」を押します。

プリセットやJSONの読み込みは現在の編集内容を置き換えます。必要な内容は先に保存してください。
フォームの未適用の値は、保存ファイルやグラフには入りません。
ブラウザ再読込・接続終了・サーバー再起動で編集中の内容を失う場合があります。自動保存はありません。
不正なJSONや不正な区間編集は適用せず、直前の有効なワークアウトを保持します。

## ZWO出力（試験機能）

**公式Workout Builderへの取り込みは、以下の4種類でユーザー確認済みです。確認範囲は区間数と合計時間の期待値との一致です。**

| ワークアウト | 区間数 | 合計時間 | 結果 |
| --- | ---: | ---: | --- |
| 計算サンプル | 3 | 10分（600秒） | 期待値と一致 |
| SST | 5 | 50分（3000秒） | 期待値と一致 |
| 4×8 | 9 | 56分（3360秒） | 期待値と一致 |
| 30/15 | 64 | 43分30秒（2610秒） | 期待値と一致 |

確認主体はユーザー、報告の記録日は2026-10-21です。Codexによる独立した取り込み再検証ではありません。
**MyWhooshアプリへの同期、実走時の出力制御、他のOSや環境での互換性は未検証です。**
個々の区間時間・区間順・FTP比率・目標Wの取り込み後の一致も、この報告だけでは確認済みとしません。
検証時の詳しい環境やファイルのハッシュは未記録であり、この4種類の結果を他のファイルや環境へ一般化しません。

- 全区間を`SteadyState Duration="整数秒" Power="FTP比率"`として順番どおりに書き出します。
- 80%FTPは`Power="0.8"`です。Wそのものや作成側FTPは埋め込みません。
- 取り込み先のFTPが異なれば、同じ比率でも目標Wが変わります。
- 反復圧縮はしません。最後の回復も元の区間リストどおり保持します。
- ウォームアップ・クールダウンも一定出力のままです。ランプに変更しません。
- ワークアウト名・説明は保持します。個別の区間名・区分・色はこの最小ZWOには保存しません。
- 再編集にはJSONを使ってください。ZWOの再読込機能はありません。
- XML 1.0で禁止された文字は除去せず拒否します。XML出力できなくてもJSON保存は独立して使えます。
- MyWhoosh側の数値範囲・最大区間数・名称・0%FTPなどの制約は未確認です。64区間の30/15を受理した結果は、最大区間数の確定を意味しません。

[出力例](examples/calculation_sample.zwo)は、300秒50%・120秒100%・180秒50%の合成データです。
合計600秒で、取り込み先FTPが250 Wなら125・250・125 W、300 Wなら150・300・150 Wが期待値です。
手動検証は[互換性と検証手順](docs/compatibility.md)を参照してください。

## プリセットの初期値

| プリセット | 主区間 | 回復 | 前後の区間 | 合計 |
| --- | --- | --- | --- | --- |
| 4×8分 | 8分×4本、105%FTP | 本の間に3分、50% | 10分50%＋5分40% | 56分 |
| 30/15 | 30秒120%＋15秒50%を10回×3セット | セット間に追加3分50% | 10分50%＋5分40% | 43分30秒 |
| SST | 15分×2本、90%FTP | 本の間に5分50% | 10分50%＋5分40% | 50分 |

30/15は各セット最後の15秒回復も含み、その後にセット間回復を追加します。
名称や強度はプリセット例の選択であり、生理学的な分類や最適処方の断定ではありません。
色は編集可能な「区分」に対応します。%FTPだけから自動分類するものではありません。
